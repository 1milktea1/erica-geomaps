# DESDR Bangladesh flood-survey geomap (local POC)

A standalone Streamlit app for exploring the Noki Bangladesh flood-year ranking survey on a map.
It reads the survey Parquet **read-only** and is not connected to Sliders or Noki.

## Run it

```bash
cd /Users/ericaz./DESDR/erica-geomaps
python3 -m venv .venv                 # skip if .venv already exists
source .venv/bin/activate
pip install -r requirements-dev.txt   # app + tests + build script
streamlit run app.py                  # opens http://localhost:8501
```

The app reads `data/EricaTest.parquet` (a copy of `../DESDR-Sliders/Sliders/EricaTest.parquet`).
To use a different export, replace that file or change `DEFAULT_PARQUET` in `processing.py`.

Run the tests with `python -m pytest -q tests`.

## Deploy (Streamlit Community Cloud)

Push this folder to a GitHub repo, then at https://share.streamlit.io choose **New app** and pick the repo and `app.py`.
The hosted app installs only `requirements.txt`. Anyone who can see the repo can see everything under `data/`,
so use a private repo and a private app before adding real survey responses.

## What's in the current data file

`EricaTest.parquet` has 35 rows in long format, with columns `start, loc_question, rank, year, comments`.

- **These are test records, not field responses.** `start` holds `Test User 1` through `Test User 7`: one respondent per location, each giving ranks 1–5.
- **Only five years appear:** 2004, 2007, 2017, 2019 and 2020.
- **Every `comments` value is empty.**
- **There are no coordinates or geometry in the file.**

The app shows a "Test data" banner and flags every statistic as a small sample (n < 5). Nothing is imputed or invented.

## Features

| Area | What it does |
|---|---|
| Map | Folium/Leaflet with zoom and pan. There is one marker per survey location, plus optional upazila boundary polygons. |
| Year selector | Slider for 2000–2020. Each marker's colour shows the **mean or median rank** for that year, darker = worse; **rank 1 = worst flood year**. Marker size shows the share of respondents who ranked the year, and popups say "N of M respondents ranked {year}". |
| No-data states | A dashed grey marker means the location has responses but nobody ranked this year (*unranked*, not "no flood"). A hollow grey marker means the location has no responses at all. |
| Location selection | Sidebar dropdown, or click a marker. Shows the top 5 most-reported years, the rank distribution, respondent counts, individual rankings and written comments. |
| Charts | Stacked bar of how often each year (2000–2020) appears in the top five, split by rank 1–5. It reads the same filtered records as the location detail panel. |
| Data tab | Detected schema, which columns were used, validated records, rejected rows with reasons, and the location gazetteer. |

## How the data is processed (`processing.py`)

`load_dataset(path)` runs these steps:

1. `load_raw`: `pd.read_parquet`. The source file is never written.
2. `normalize`:
   - **Find columns.** Detects the columns by name: respondent, location, rank, year and comments. A wide `rank_1…rank_5` export is melted to long format; blank rank cells are skipped, not imputed.
   - **Match locations.** Location names are matched to the gazetteer case- and whitespace-insensitively, including alias spellings (e.g. `Fulchhari`, `Saghata`).
   - **Validate.** Rows go to `issues` with a reason if the year is not 2000–2020 or the rank is not 1–5. Rows are also rejected for an unknown location, the same rank or year twice for one respondent, or one respondent at several locations.
3. **Statistics:** `year_location_stats`, `year_frequency`, `top_years` and `comments`.

Rankings are treated as **ordinal opinions**. The app reports counts, mean/median rank and rank distributions, never "flood intensity". A year that is not in a respondent's top five contributes no rank value.

## Geographic reference

`data/locations.csv` and `data/upazilas_subset.geojson` are generated by `scripts/build_reference.py`. The source is the **Bangladesh COD-AB upazila boundaries**: Bangladesh Bureau of Statistics via OCHA/HDX (https://data.humdata.org/dataset/cod-ab-bgd), licence CC BY-IGO.

Marker positions are each polygon's `representative_point()`, which always falls inside the upazila. They are not hand-entered. See `data/SOURCES.md`.

**Sherpur is an inference.** The survey says only "Sherpur". This app maps it to **Sherpur Upazila in Bogura**, not Sherpur Sadar in Sherpur district, because the other six locations are riverine upazilas in Kurigram, Gaibandha and Bogura. Confirm this with the survey team. To change it, edit `SURVEY_TO_UPAZILA` and rerun `python scripts/build_reference.py`; that downloads about 33 MB from HDX.

## Limitations

- The current file is test data: n = 1 per location, five distinct years and no comments. None of the patterns it shows mean anything yet.
- `start` holds respondent labels, not timestamps, so there is no time filter. If a real export puts timestamps there, the app notes it on the Data tab.
- Basemap tiles come from OpenStreetMap and need internet access. All survey and boundary data is local.
